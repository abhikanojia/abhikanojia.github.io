<div class="quick-answer" markdown="1">
**Quick answer:** `allow_browser` is a controller macro, added in **Rails 7.2**, that turns away browsers older than the versions you list. It renders `public/406-unsupported-browser.html` with HTTP **406 Not Acceptable**. New Rails 7.2 and Rails 8 apps put `allow_browser versions: :modern` in `ApplicationController`. If real users are seeing "Your browser is not supported", remove that line or replace `:modern` with explicit, lower versions.
</div>

> **Version note:** this post originally said `allow_browser` shipped in Rails 8.0. It actually landed in Rails 7.2 and is part of the default app template in Rails 7.2 and Rails 8.

## # What `allow_browser` does

```ruby
class ApplicationController < ActionController::Base
  # Generated by default in new Rails 7.2+ / Rails 8 apps
  allow_browser versions: :modern
end
```

Before each action, Rails checks the request's User-Agent against the versions you allow. If the browser is older, the request stops there and the user gets the 406 page.

`:modern` means browsers that natively support WebP images, web push, badges, import maps, CSS nesting and CSS `:has`. In practice that's roughly Safari 17.2+, Chrome 120+, Firefox 121+ and Opera 106+, with Internet Explorer blocked. This is aimed at new apps using import maps and modern CSS. It can surprise an existing app, because users on older iPhones that can't update Safari will be blocked.

## # Why users suddenly see "Your browser is not supported"

This usually happens after upgrading an existing app or copying the new default `ApplicationController` into it. The app works for the team on current browsers, while some customers, often on older iOS devices or locked-down corporate machines, get a 406. Check your logs for `406` responses after the deploy.

## # How to relax or remove it

**Remove it entirely** if your app doesn't depend on those modern browser features. Delete the `allow_browser` line from `ApplicationController`.

**Set explicit versions** if you want a floor that's lower than `:modern`:

```ruby
class ApplicationController < ActionController::Base
  allow_browser versions: { safari: 16, chrome: 110, firefox: 110, opera: 95, ie: false }
end
```

Browsers you don't list are **allowed**. `false` blocks a browser completely, which is what `ie: false` does here.

**Limit it to specific actions** with `only` or `except`, just like a callback:

```ruby
class ChatController < ApplicationController
  allow_browser versions: { chrome: 85, opera: 100, ie: false }, only: :show
end
```

If you want to keep the check but only on the screens that truly need modern features, move `allow_browser` out of `ApplicationController` into those controllers.

## # Customizing the blocked response

By default Rails renders `public/406-unsupported-browser.html`. You can edit that file, or pass `block:` to handle it yourself:

```ruby
class ApplicationController < ActionController::Base
  allow_browser versions: :modern, block: :handle_outdated_browser

  private
    def handle_outdated_browser
      render "errors/unsupported_browser", status: :not_acceptable
    end
end
```

Requests without a recognizable browser User-Agent (API clients, health checks, most bots) are not blocked.
